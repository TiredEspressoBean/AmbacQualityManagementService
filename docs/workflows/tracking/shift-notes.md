# Shift Notes

**Hand off to the floor** — notes operators see on their home screen and
acknowledge.

**Production** > **Shift Notes** (`/production/shift-notes`)

## What they're for

Shift notes carry the things that don't belong in a work order but the next
shift needs to know: a machine behaving oddly, a material substitution, a
customer visit, a changed priority.

Unlike a message, a shift note can **require acknowledgment**, so you can see
who has actually read it.

## Writing a note

1. Click **New note**
2. Write the note
3. Choose the **audience**
4. Optionally mark it **High priority** or **Requires acknowledgment**
5. Post it

### Audience

Default is **everyone on the floor**. You can narrow it to specific roles:

Auditor · Customer · Document Controller · Engineering · Operator ·
Production Manager · Purchasing · QA Inspector · QA Manager · Shift Lead ·
Tenant Admin

Narrow the audience when a note is only relevant to one group — a note everyone
must dismiss but few need trains people to dismiss without reading.

### High priority and acknowledgment

| Option | Effect |
|--------|--------|
| **High priority** | The note is surfaced more prominently |
| **Requires acknowledgment** | Recipients must confirm they've read it, and you can see who has |

Reserve acknowledgment for things with a consequence if missed. It's the only
signal that separates "posted" from "read".

## Where operators see them

Shift notes appear on the operator home screen, so they're read at the start of
a shift rather than sought out.

Notifications for shift notes are routed by a starter notification rule — see
[Notification Rules](../../admin/setup/notification-rules.md).
