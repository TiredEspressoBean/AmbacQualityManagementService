# Creating Orders

Orders represent customer requests to manufacture or process parts. This guide covers creating and configuring orders.

## Before You Start

Ensure you have:

- Permission to create orders
- Customer records configured in the system
- Part types defined for the products you'll manufacture

## Creating a New Order

1. Navigate to **Data Management** > **Orders**
2. Click **New Orders** in the top right
3. Complete the order form

### Required Fields

| Field | Description | Tips |
|-------|-------------|------|
| **Order Name** | Your reference name/number | Use your PO/SO number format |

Order Name is the only required field — everything else, company included, can
be left blank and filled in later.

!!! info "Order Number"
    The system automatically generates a unique order number (e.g., `ORD-2026-0001`). The **Order Name** field is where you enter your own reference like the customer PO number.

### Optional Fields

| Field | Description |
|-------|-------------|
| **Company** | Company placing the order |
| **Customer** | The customer contact on the order |
| **Estimated Completion** | Target completion date |
| **Order Status** | Current state of the order |
| **Archive Order** | Archive the order instead of keeping it active |

4. Click **Create Order**

!!! note "Priority is set on the work order"
    Orders have no priority field. Priority (**Urgent**, **High**, **Normal**,
    **Low**) is set on the *work order* that carries the production, not on the
    customer order.

## Order Numbering

Order numbers are automatically generated by the system in the format `ORD-YYYY-NNNN` (e.g., `ORD-2026-0001`).

Use the **Order Name** field to enter your own reference number such as the customer PO number or sales order number.

## Order Status

A new order starts **Pending** unless you choose another status on the form. An
order created through the API must carry a status. An import row with no status
is imported as **Pending**; one whose status is not one of the six is imported
as **Pending**, with a warning.

Status is set by hand — on the order form, or by import — with one exception: an
order becomes **Completed** on its own once every work order on it is completed
or cancelled and at least one was completed. Reopening a completed work order,
or reversing a shipment on it, puts the order back to **In Progress**.

| Status | Meaning |
|--------|---------|
| **RFI** | Request for Information - awaiting clarification |
| **Pending** | Order created, not yet in production |
| **In Progress** | Work has begun, parts are being processed |
| **On Hold** | Order paused (quality issue, customer request) |
| **Completed** | All parts finished |
| **Cancelled** | Order cancelled |

## Linking to Work Orders

Orders need work orders to track production:

1. Go to **Data Management** > **Work Orders** and click **New Work Orders**
2. Enter the **ERP ID** and **Expected Completion Date** — both required
3. Pick your order as the **Related Order**
4. Choose the **Process** to apply — only approved processes in force are offered
5. Click **Submit**. The work order starts **Pending**, with 0 parts started

See [Creating a Work Order](../work-orders/basics.md#creating-a-work-order) for
every field, and for how its quantity and parts are set.

## Bulk Order Import

For creating multiple orders:

1. Navigate to **Data Management** > **Orders**
2. Click **Import**
3. Download the CSV template
4. Fill in order data
5. Upload the completed file

The system validates the import and reports any errors.

## Order Permissions

| Action | Required Permission |
|--------|---------------------|
| View orders | `view_orders` |
| Create orders | `add_orders` |
| Edit orders | `change_orders` |
| Delete orders | `delete_orders` |

Customer users see only the orders they are named on — orders where they are
the customer, or where they have been added as a viewer. Access is granted per
person, not per company, so adding a colleague to the same company does not
give them the order.
